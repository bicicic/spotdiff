# 検証計画と受入条件

## 初版の実行結果（2026-09-27）

- TypeScript型検査とGitHub Pages用ビルド：成功。
- 単体テスト：13件成功。
- 本番ビルドのブラウザテスト：Chromium 9件、WebKit 9件、計18件成功。すべて`/spotdiff/`サブパスで実施。
- 開発サーバーでもChromiumによる画像入力・比較・感度変更・再比較のフロー1件が成功。
- 入力・結果のスクリーンショットを確認。画像の外部送信がないこともブラウザテストで確認。
- WebKit実行に必要なLinuxライブラリは検証環境の一時ディレクトリに展開して使用。通常の環境ではPlaywrightの`install-deps`で準備できる。
- 以下の実機受入は未実施。自動テスト成功を実写全般の精度保証とは扱わない。

## 自動検証

`npm test`では4隅の妥当性（交差・逆順・画面外・狭小・NaN）、共通寸法、プレビューの四隅写像、感度の単調性、MADゼロ、外れ値への耐性、一様な背景での明暗過補正の防止、戻る状態を検証する。

`npm run build`で型検査と公開物生成。`npm run test:e2e`ではChromiumとiPhoneサイズのWebKitで本番ビルドを操作し、実際のOpenCV Workerを検証する。

ブラウザテストはコードで再現可能な図形FixtureをCanvasに描き、PNGとして読み込ませる。外部画像やネットワーク素材には依存しない。主な項目は、色変更・物の削除の検出、同一画像で候補ゼロ、全体的な暗さの補正、傾き・縮小・ノイズの補正、感度変更と表示設定の保持、戻る・リセット、中断後の再比較、壊れた画像の回復、10MB超の拒否、4隅のドラッグ・無効領域・回転・キーボード操作、外部リクエストがないこと。

## 公開検証

`docs/`をHTTPサーバーのサブパスから配信し、HTML・CSS・Worker・OpenCV資産が取得でき、実際の比較が完了することを確認する。`.nojekyll`とライセンスを含むことも確認する。`docs/`内に設計資料を置かない。

## 実機受入（自動テストとは別）

- 最新iPhone Safari／Android Chromeで標準カメラ起動、写真選択、EXIF方向、90度回転、ドラッグ・ルーペ、画面回転を確認する。
- 10MB・2,400万画素の境界、1600px処理画像、反復比較時のメモリ、処理中の応答性を確認する。
- 同じ絵を角度・距離・明るさを変えて撮影したペアと、色・形・追加・削除の正解が分かるペアで検証する。
- 検出率は正解箇所のうち候補として発見できた割合、誤検出は正解と対応しない候補領域数。正解の矩形またはマスクを記録し、対応判定ルールと検証セットを固定してから数値を合意する。
- 初回比較10秒以内は目標。画像読込とOpenCV初期化を除いて計測し、使用端末・OS・ブラウザ・入力寸法を記録する。

## 未確定・未検証

受入端末、実写セット、箇所対応の判定基準、検出率と誤検出数の合格値は未確定。候補値「検出率90%以上・誤検出平均2か所以内」を合格済みとは扱わない。WebKitエミュレーションはiPhone実機試験の代替ではない。強い影・反射・湾曲・微小な点や細線は保証対象外。
